Frame order

The reference frame supplies the native ordering. The source adds shared indirect lighting before skin scattering and reconstruction before bloom preparation. Transparent effects occur in several groups. Secondary views and utility jobs can have separate targets and recording schedules.

Scene inputs →

Camera and scene size → fog preparation → opaque and masked surfaces → decals → object and camera motion → native AO and ambient lighting.

Lighting →

Local and directional lights with Enhanced Shadows → diffuse copy and source preparation → shared indirect lighting → both skin scatters → deferred composition and fog.

Remaining scene →

Visible sky and clouds → forward objects → native SSR → ocean and remaining particles, liquids, and rain → brightness measurements.

Reconstruction and output

TAA, FSR, or DLSS → bloom → DoF → flare-layer composition → motion blur → grading and late tonemap → FXAA bypass or native FXAA → UI → display encoding.

The preferred reconstruction entry is immediately before the qualified CopyReductionX4 0x72C1D157 draw. Its position in the reference frame is before EID 47966. Bloom and DoF therefore use the reconstructed scene. Supported later entries provide recovery when that opportunity is absent.

MGSV applies early color treatment in some scene shaders as well as a late tonemap. Float scene storage can contain encoded RGB. Each replacement follows the producer and view conversion at its actual position. Color and ordering contracts

Lighting and reflection handoffs

  1. Capture material meaning beside native geometry.

    Qualified opaque and wet-material replacements preserve the original outputs and add clean material color and exact surface ownership guides. Small readiness and composition masks are reset by native surface writes. Rain variants 0x2C230875 and 0xC3538951 have their own original two-target layout.

    Material capture · Qualified shader inventory

  2. Keep ambient diffuse separate from direct light.

    SSLighting2_SH_SkyLight_Encode 0x4FBDBB39 identifies the ambient family. BilateralUpscale2x2 0x844CE327 supplies small-grid ambient at pixel t0, depth at t2, phase weights at t3, sampler s8, and the original vertex/pixel b5 ranges. The later application reproduces this upsample to isolate the ambient contribution.

    Ambient capture · Full-resolution application

  3. Apply direct-light shadows inside the native light draws.

    PCSS filters native sun/moon, spot, and point shadow maps. Bend contacts read camera depth and the exact light and scene constants. Compatible unshadowed local-light groups share setup, clear, and trace dispatches in a packed atlas. Shadow-map jobs and unsupported groups use the per-light route. The spot contact budget defaults to 34.

    Contacts and soft map visibility affect direct diffuse and direct highlights. Native environment reflections, projected masks, fades, and alpha keep their separate roles. Local-light jitter is written once into the completed native packet before its workers inherit it.

    Shadow algorithm and coverage · Bend batching · Owned light-packet correction

  4. Prepare shared radiance in the existing diffuse copy.

    CopyBuffer 0xD71E843E reads original diffuse at t0 and material at t1. Target 0 retains the native diffuse and skin-mask alpha. Added inputs t18–t22 qualify albedo, normal, depth, clean color, and owner guides. Target 1 writes FP32 outgoing diffuse radiance for both diffuse and specular searches. A valid black source still blocks light.

    Supported sun/environment draws separately capture environment RGB at target 2 and retain the matching palette t10 and Fresnel t9. Immutable lookup tables are reused. Mutable tables are copied in their native command stream.

    Source preparation · Environment and table capture

  5. Trace and filter shared indirect light before skin scattering.

    The first scatter, compute 0x6DAF0C4A, supplies copied diffuse t0, depth t1, normals t2, and 64-byte geometry b0. After submitting the native prefix, one trace shares depth samples between AO, diffuse GI, bitmask specular visibility, and broad reflected light. A focused GGX ray covers narrower lobes. The trace also writes the current material guide.

    One temporal pass shares geometry and reprojection setup while accepting each signal independently. Paired reflected light and remaining environment use matching weights. Three default A-Trous passes retain the center and sample one quarter of the neighbor pattern. The final full-resolution application makes six default dispatches in total. Coarse depth sampling adds four optional reductions. The BRDF table is initialized once when needed.

    The default lighting grid contains one quarter of the render pixels, with each axis divided by two and rounded up. Search radius is expressed in output pixels. Lighting noise uses the scene-reserved jitter sample when reconstruction is enabled. Lighting maintains its own submitted history and replay rules.

    Full algorithm and signal rules · Input checks and scheduling · Trace · Temporal accumulation · Spatial filter

  6. Apply diffuse and resolve the reflection pair.

    Diffuse becomes direct + ambient × AO + diffuse GI. Missing ambient capture skips custom diffuse AO. With the feature enabled, the six supported deferred shaders bypass native diffuse AO even if custom dispatch fails, so that failure case currently has no diffuse AO.

    Both native skin-scattering passes still run once, with the original vertical bytecode for 0xB2601810. The application resolves reflected color and remaining environment to two full-resolution images. Readiness marks produced pixels. Deferred composition marks actual use only after consuming them.

    Reflection outputs and masks · Registration and scatter callbacks

  7. Compose before fog, then retain native SSR detail.

    Six supported deferred variants preserve direct highlights and replace qualified overlapping material-cube and environment response with screen light plus remaining environment. Their added t16–t21 inputs carry captured environment, visibility, reflected color, remaining environment, clean material, and readiness. Native fog, rain, and early color treatment follow within those draws.

    Native SSR remains later in the scene. Its mask, trace, reduction, and Gaussian chain feed the original complementary scene blend. The compositor retains custom lighting where a native hit contributes nothing. The sortie floor keeps native planar tracing. The older separate enhanced-SSR compute experiment is parked.

    Screen-light GGX and the game's integrated Blinn-Phong environment form the current approximation. Screen-visible diffuse source radiance also limits which reflection content the custom search can recover. Wider material, off-screen, and directional transport work remains ahead.

CPU recording, submission, and GPU execution

The columns below describe dependencies. Workers can record overlapping scenes and effects. A finished command list retains its recorded commands until submission. GPU completion requires completion evidence. Column widths and list positions have no timing scale.

Scene preparation

  1. The shared Dg renderer rebuilds scene resources when the native size plan changes.
  2. A native scene build publishes renderer, viewport, presentation, and generation identity.
  3. Main camera setup reserves jitter and saves the original matrices for that scene.
  4. Plugin branches and copied subcontexts carry that identity into worker jobs.

Parallel worker recording

  1. Lighting, scene effects, flares, and UI can record on different deferred contexts.
  2. Every routed draw selects the scene's retained output and exact resource roles.
  3. FinishCommandList transfers output references and ownership metadata to the native list.
  4. Display recording closes the open sequence. Late workers still find that scene's producer and clears.

Ordered submission and execution

  1. Native dependency traversal submits completed lists in its required order.
  2. The coordinator preserves prefixes and remainders around custom immediate-context work.
  3. Successful reconstruction installs output, then commits its camera-history endpoint.
  4. Remaining post-processing, UI, and display work consume the retained output. GPU queries can establish completion.

A worker finishing display recording before a flare worker is a supported order. Earlier native clears move into the output producer when its allocation is acquired. The producer keeps them until reuse, allowing that late worker to initialize the enlarged flare layer. Startup scenes that never acquire output retire their pending clear records at display completion.

Output reuse waits for recording contexts, open sequences, and native command lists to release their references. Compatible spare allocations support concurrent scenes. A cached list replay preserves native work. Reconstruction uses the spatial fallback for that repeated observation, Bend recomputes contacts, and indirect lighting consumes its copy association once.

  1. The deferred SH correction runs at packet attachment 0x283B90 inside producer 0x281EF0.
